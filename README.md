# KeyLimiter

Программа для Windows, ограничивающая частоту нажатий выбранных клавиш
и автоматически нажимающая Enter в заданное время.
По умолчанию: **Enter — не более 6 нажатий за 1 секунду**; при превышении клавиша
глушится на 1 секунду.

## Как это работает

Ставится низкоуровневый клавиатурный хук Windows (`WH_KEYBOARD_LL`). Для каждой
клавиши из правил ведётся скользящее окно нажатий. Как только за окном набирается
больше лимита, нажатия перестают доходить до приложений на время блокировки.

Важное поведение: **нажатия во время блокировки её не продлевают** — таймер
отсчитывается от момента срабатывания лимита. Удержание клавиши (авто-повтор)
лимит не расходует.

## Получить .exe

Готовый `KeyLimiter.exe` собирается автоматически на GitHub Actions:

1. Открыть вкладку **Actions** в репозитории.
2. Выбрать последний успешный запуск workflow `build`.
3. Скачать артефакт **KeyLimiter-exe**.

Для тега `vX.Y.Z` exe дополнительно прикрепляется к GitHub Release.

Собрать локально на Windows:

```
pip install -r requirements.txt pyinstaller
pyinstaller --clean --noconfirm build.spec
```

Результат — `dist/KeyLimiter.exe`.

## Использование

Запустить `KeyLimiter.exe`. Откроется окно со списком правил:

| Поле | Смысл |
|---|---|
| Клавиша | имя клавиши (`ENTER`, `SPACE`, `A`, `F5`, `NUMPAD1`, …) |
| Лимит | сколько нажатий разрешено в окне |
| Окно, мс | длительность окна подсчёта |
| Блокировка, мс | на сколько глушится клавиша при превышении |
| Вкл. | учитывается ли правило |

- **Добавить / Изменить / Удалить** — правки применяются к хуку сразу, без перезапуска.
- В диалоге правила кнопка **«Записать клавишу»** подставит имя следующей нажатой клавиши.
- **Ctrl+Alt+P** — глобальная пауза/возобновление (на случай, если правило мешает).
- Закрытие окна сворачивает в трей; полный выход — из меню трея.
- Ключ `--headless` запускает программу сразу в трее.

### Таймеры Enter

1. На вкладке **«Таймеры Enter»** выбрать **часы, минуты и секунды** запуска,
   часовой пояс, количество нажатий и интервал между ними в миллисекундах.
   По умолчанию выбран **MSK — Москва (`Europe/Moscow`)**. В списке можно выбрать
   другой пояс, например `UTC`, `Asia/Tokyo` или `Europe/Berlin`, либо ввести
   его IANA-имя.
2. Нажать **«Добавить таймер»**. Повторить для остальных таймеров — каждый хранит
   собственные время, пояс, количество нажатий и интервал. В списке отображаются
   номер, параметры и состояние каждого таймера.
3. Выбрать таймер и нажать **«Запланировать»** или нажать **«Запланировать все»**.
   Дата запуска показывается в состоянии таймера, полный момент — в журнале,
   в выбранном поясе. Если время сегодня уже прошло, запуск назначается на завтра
   по календарю этого пояса. Уже работающие таймеры при запуске всех не перезапускаются.
4. Переключиться в нужное окно: Enter отправляется в **активное окно** в момент
   каждого нажатия. Программа должна оставаться запущенной; сворачивание в трей
   не мешает выполнению.

Каждый таймер выполняется **однократно** и независимо от остальных. Если несколько
таймеров срабатывают одновременно, выполняются все их серии; количества нажатий
складываются. Интервал каждого таймера отсчитывается отдельно.

- **«Отменить»** останавливает только выбранный таймер; **«Отменить все»** — все.
- **«Стоп»** и **Ctrl+Alt+P** отменяют все ожидающие и выполняющиеся таймеры.
  Возобновление программы не возвращает отменённые задания — их нужно запланировать снова.
- Для правки выбрать таймер, изменить поля и нажать **«Применить к выбранному»**.
  Ожидающий или выполняющийся таймер перед правкой нужно отменить.
- **«Удалить таймер»** удаляет выбранный таймер и отменяет его оставшиеся нажатия;
  остальные таймеры продолжают работать.

Список таймеров сохраняется в `config.json` при добавлении, изменении и удалении.
Кнопка **«Сохранить»** также сохраняет текущие поля как параметры для создания
следующего таймера; для изменения существующего используется **«Применить к выбранному»**.
После перезапуска список сохраняется, но таймеры нужно снова запланировать.
Количество и интервал должны быть целыми числами больше нуля.

Часовой пояс компьютера не влияет на время запуска. Для поясов с переходом
на летнее время выбирается ближайший существующий момент: время, пропущенное
при переводе часов вперёд, переносится на следующий день; при повторе часа
выбирается ближайшее из двух совпадающих времён. Задание выполняется один раз.

Собственные автоматические нажатия обходят ограничитель, поэтому правило
Enter не уменьшает заданную серию. Остальные программные нажатия по-прежнему
обрабатываются согласно `count_injected`.

Проверка времени происходит примерно раз в 50 мс; это не таймер реального
времени. Интервал между нажатиями может быть больше заданного при нагрузке.
После сна или задержки интерфейса просроченное задание начнётся при следующей
проверке, а пропущенные интервалы не догоняются пачкой.

## config.json

Лежит рядом с exe, создаётся при первом запуске и обновляется при изменении правил.

```json
{
  "enabled_on_start": true,
  "pause_hotkey": "ctrl+alt+p",
  "count_injected": true,
  "auto_enter": {
    "time": "12:00:00",
    "timezone": "Europe/Moscow",
    "count": 5,
    "interval_ms": 200
  },
  "timers": [
    { "time": "12:00:00", "timezone": "Europe/Moscow", "count": 5, "interval_ms": 200 },
    { "time": "15:30:45", "timezone": "UTC", "count": 3, "interval_ms": 500 }
  ],
  "rules": [
    { "key": "ENTER", "limit": 6, "window_ms": 1000, "block_ms": 1000, "enabled": true }
  ]
}
```

- `enabled_on_start` — начинать работу сразу или в режиме паузы.
- `count_injected` — учитывать ли программно сгенерированные нажатия (макросы,
  автокликеры). `false` — такие события пропускаются мимо лимитера.
- `auto_enter` — последние параметры формы для добавления таймера.
- `timers` — список сохранённых таймеров. Старые конфиги с одним `auto_enter`
  автоматически переносятся в этот список. Некорректные таймеры пропускаются
  с записью в лог; остальные сохраняются. Пустой список поддерживается.
- Если поле `timezone` отсутствует, используется `Europe/Moscow` (также можно указать `MSK`).

Некорректное правило (неизвестная клавиша, ноль или не-число) отбрасывается при
загрузке с записью в лог; программа при этом не падает.

## Ограничения

- Только Windows: используется WinAPI-хук.
- Нажатия в окнах, запущенных **от администратора**, не перехватываются, если сам
  KeyLimiter запущен без прав администратора. Для таких приложений запускайте exe
  через «Запуск от имени администратора».
- Автоматический ввод через [Windows SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)
  также требует достаточных прав для активного окна. Если отправка не удалась,
  серия отменяется, а ошибка записывается в журнал.
- Антивирус может ругаться на PyInstaller-сборку с клавиатурным хуком — это
  ожидаемо для такого класса программ. Помогает подпись сертификатом или
  добавление файла в исключения.

## Разработка

```
pip install -r requirements.txt pytest
pytest -q
```

Логика лимитера, планировщика и разбор конфига не зависят от WinAPI,
поэтому их тесты гоняются на любой ОС. Отправка Enter проверяется с подменой
`SendInput`; взаимодействие с хуком дополнительно проверяется в Windows CI.
Для Windows требуется база часовых поясов `tzdata`, используемая
[Python zoneinfo](https://docs.python.org/3/library/zoneinfo.html#data-sources).
Она установится из `requirements.txt` и включается в `.exe` через `build.spec`.
